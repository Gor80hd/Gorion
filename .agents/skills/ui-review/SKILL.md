# Ревью интерфейса

## 1. Подготовка

- Прочитай `DESIGN.md` целиком (он короткий) и `design/tokens.json` → нужные разделы.
- Найди код экрана и его компоненты; составь список элементов на экране.

## 2. Статическая проверка кода

Ищи и перечисляй с `файл:строка`:

- числа цвета, размера, отступа, радиуса, длительности вне сгенерированных токенов;
- `.linear`, `.easeIn*`, `.easeOut*`, `.default`, фиксированные `duration` для
  движения/масштаба; `withAnimation` без пружины из токенов;
- перелёт прозрачности или цвета (bounce > 0 на opacity/color);
- элементы, блокирующие ввод на время анимации;
- стекло внутри стекла (`glassEffect` у потомка стеклянного островка);
- интерактивные элементы без подписи доступности; зоны нажатия меньше `minHitTarget`;
- технические слова в текстах вне раздела «Протоколы» (TUN, outbound, inbound, SNI…).

## 3. Живая проверка

- Собери и запусти приложение (команды — AGENTS.md → «Команды»).
- Сними экран: тёмная и светлая тема, окно по умолчанию и минимальное 940×600.
- Включи «Уменьшить движение» и «Снизить прозрачность» — сними снова.
- Проверь движение руками: прерви анимацию на середине (быстрый повторный
  щелчок, смена направления), брось перетаскиваемый элемент — движение
  должно продолжаться без рывка.
- Пройди экран с клавиатуры (Tab, пробел, Esc) и VoiceOver.

## 4. Отчёт

По пунктам чек-листа DESIGN.md → «Проверка экрана»: ✓ / ✗ с доказательством
(скриншот, `файл:строка`). Для каждого ✗ — конкретное исправление.
Сначала то, что мешает человеку понять экран; потом — визуальные мелочи.
Если что-то проверить не удалось (нет VoiceOver, не собралось) — так и напиши.
