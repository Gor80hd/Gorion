# Перенос функции

Цель — новое приложение делает то же, что Flutter-версия, и не теряет
исправлений, накопленных в эталоне.

## 1. Найди место в плане

- Строка в `docs/migration/parity.md` и шаг в `docs/migration/PLAN.md`.
  Нет строки — добавь её (функция, источник, статусы `—`).
- Поставь статус `◐` в колонке, над которой работаешь.

## 2. Прочитай эталон целиком

Flutter-версии в рабочем дереве больше нет: эталон — коммит `166ab89`
(последний, где лежат `lib/` и `test/`). Читать так:

```bash
git show 166ab89:lib/путь/к/файлу.dart
git grep -n 'слово' 166ab89 -- lib test
git worktree add ../gorion-flutter 166ab89   # целиком, если файлов много
```

- Файлы из колонки «Источник Flutter» и всё, что они вызывают.
- Тесты: `test/` повторяет структуру `lib/` — найди соответствующие `*_test.dart`.
- `docs/runtime-audit.md` — если функция касается прокси, процессов, TUN, помощника.
- Выпиши поведение списком: входы, выходы, ошибки, граничные случаи, побочные
  эффекты (файлы, процессы, системные настройки). Этот список — критерий приёмки.

## 3. Зафиксируй поведение

- Для логики без побочных эффектов (разбор, сборка конфига, сортировки,
  фильтры): добавь случаи в `tool/export_golden.dart` в рабочей копии
  `166ab89` (`git worktree`, там же `flutter pub get`) и выгрузи фикстуры в
  `core/fixtures/<область>/` этого репозитория. В фикстурах не должно быть
  настоящих ссылок, ключей и адресов серверов — только синтетические.
- Для побочных эффектов: перенеси сценарии тестов эталона в Rust-тесты с
  подменой системы (fake runner, временные каталоги).

## 4. Ядро (`core/`)

- Логика → `gorion-core`, системное — там же под `cfg(target_os)`; подключение — `gorion-engine`.
- Ошибки — перечисления с кодами; текстов для пользователя нет.
- Тесты: фикстуры + перенесённые сценарии. `cargo test`, `cargo clippy -D warnings`.
- Новое в публичном API → `gorion-ffi` (UniFFI): async-команды, события через наблюдатель.

## 5. Интерфейс

- Перечитай нужные разделы `DESIGN.md`: компоновка, компонент, движение, тексты.
- Только токены (`GorionDesign` / модуль токенов Windows). Только пружины и инерция.
- Тексты — по разделу «Тексты»; эталонные англоязычные/технические подписи
  не копируй, а переписывай.
- Модели — `@Observable`, `@MainActor`; ядро не вызывается из `View` напрямую.

## 6. Проверка

- Тесты и линтеры зелёные, без предупреждений.
- Запусти приложение и пройди сценарий руками; сделай скриншоты светлой и тёмной темы.
- Навык `ui-review` или агент `design-reviewer` для интерфейса.
- Агент `parity-auditor` с путями эталона и новой реализации — для потерянного поведения.
- Сетевые проверки — по правилам AGENTS.md (не включать TUN без просьбы,
  здоровье — только сквозными сигналами).

## 7. Закрой

- `parity.md`: `●` (или `Δ` с причиной), `PLAN.md`: `[x]`.
- В ответе: что сделано, чем проверено, что **не** проверено.
