# ADR-0001. Общее ядро на Rust, интерфейс нативный

Статус: **принято** · 2026-11-11 (владелец подтвердил: логика единая, интерфейсы нативные)

## Контекст

Логика Gorion — около 25 тыс. строк Dart из 39: разбор подписок, сборка
конфигурации sing-box, автовыбор, замеры, системный прокси, watchdog, помощник.
Она годами доводилась на реальных сбоях (см. `docs/runtime-audit.md`).
Интерфейс переносится на SwiftUI (macOS) и Rust (Windows). Вопрос: на каком
языке будет логика.

## Варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| **A. Общее ядро на Rust**, Swift вызывает его через UniFFI | логика пишется и тестируется один раз; Windows-приложение на Rust использует ядро напрямую; один помощник на обе ОС | FFI-слой; на Mac нужен Rust-тулчейн; XCFramework в сборке |
| B. Ядро на Swift для macOS, отдельно на Rust для Windows | на Mac только Swift, проще отладка | вся логика пишется дважды и расходится; исправления сети нужно делать в двух местах |
| C. Оставить ядро на Dart (headless), интерфейс нативный | ничего не переписывать | Dart-рантайм в нативном приложении, IPC, две модели сборки — тот же тупик с другой стороны |
| D. Общее ядро на Go | sing-box тоже на Go — можно встроить его в процесс | gomobile даёт неудобные Objective-C-привязки с узким набором типов; второй рантайм со сборщиком мусора и своими сигналами внутри приложения; из Rust/C# на Windows — только C ABI вручную |

Почему не Go, хотя sing-box на Go: ядро Gorion запускает sing-box отдельным
процессом (и в помощнике для TUN) — встраивать его не нужно. А когда понадобится
NetworkExtension, libbox (Go-сборка sing-box) живёт в расширении отдельно от ядра.

## Решение

Вариант A. `core/` — Cargo workspace, Swift получает типы и async-функции из
UniFFI, события ядра приходят через callback-наблюдатель и превращаются в
`@Observable`-модели на главном акторе. Специфичное для ОС (системный прокси,
процессы, помощник) живёт в `gorion-platform` под `cfg(target_os)`.

Исключение: то, что требует системных фреймворков Apple и не нужно Windows
(`SMAppService`, `MenuBarExtra`, NetworkExtension в будущем), пишется на Swift.

## Последствия

- Поведение фиксируется золотыми фикстурами из Flutter-версии до переписывания.
- Строки для пользователя ядро не содержит: только коды ошибок и данные.
- Сборка macOS требует `rustup` и скрипт `core/scripts/build-xcframework.sh`.
- Привязки: Swift — официальный `uniffi-bindgen`; для C# (если Windows-интерфейс
  будет на WinUI 3) — `uniffi-bindgen-cs` или C ABI.
