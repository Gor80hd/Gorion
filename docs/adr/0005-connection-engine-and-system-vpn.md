# ADR-0005. Движок подключения и системный VPN

Статус: принято (движок — вариант А, системный VPN — вариант Г) · 2026-11-12

## Контекст

Владелец хочет:

1. Чтобы VPN включался одной кнопкой на уровне системы, как в других
   VPN-приложениях на macOS, без режимов «Приложения / Вручную».
2. Чтобы подключение вела своя библиотека на Rust, без отдельного sing-box и
   без смеси языков. Настройки и протоколы — как в Xray и sing-box.

Что есть сейчас:

- Ядро на Rust (`core/`) разбирает подписки и ссылки: VLESS (включая
  REALITY), VMess, Trojan, Shadowsocks, Hysteria2, TUIC, AnyTLS; транспорты
  ws, grpc, httpupgrade. Нет XHTTP — он есть только в Xray.
- Само шифрование и передачу трафика делает sing-box. Он запускается
  отдельным процессом (`runtime/`).
- Режим «весь компьютер» (TUN) ждёт привилегированного помощника. Поэтому
  сейчас на выбор только системный прокси и локальный прокси.

Факты, которые ограничивают выбор:

- **Системный VPN на macOS.** Вне App Store его делают через Network
  Extension (`NEPacketTunnelProvider`) в виде **системного расширения**.
  Для этого нужны подпись Developer ID, права `packet-tunnel-provider-systemextension`
  и `system-extension.install`, нотаризация. Всё это требует платного
  аккаунта Apple Developer. Без него остаётся привилегированный помощник
  (launchd), как во Flutter-версии: трафик тоже идёт через систему, но VPN
  не появляется в «Системных настройках → VPN».
- **Готового ядра на Rust нет.** Встраиваемой библиотеки на Rust, которая
  умела бы VLESS + REALITY + Vision, Hysteria2, TUIC, AnyTLS и TUN вместе, не
  найдено. Ближе всех `shoes` (VLESS, Hysteria2, REALITY), но это сервер, а
  не библиотека; `clash-rs` — без подтверждённой REALITY.
- **Маскировка под браузер.** Против блокировок важно, чтобы TLS-рукопожатие
  выглядело как у Chrome (uTLS в Go). В Rust зрелой замены нет. Её можно
  собрать на BoringSSL (крейт `boring`), но это отдельная большая работа с
  риском, что сервер нас отличит.

## Варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| А. Свой движок на Rust с нуля | один язык; полный контроль; одна библиотека для macOS и Windows | месяцы работы; REALITY, Vision, QUIC, маскировка TLS и TUN-стек — каждый из них сложен; ошибка = утечка или блокировка |
| Б. Ядро на Rust ведёт всё, sing-box встроен библиотекой внутри Network Extension (как официальный клиент sing-box для Apple) | системный VPN одной кнопкой; нет отдельного процесса; проверенные протоколы и маскировка | Go остаётся внутри; нужен аккаунт Apple Developer |
| В. Поэтапно: Б сейчас, свои протоколы на Rust по одному (Shadowsocks → Trojan → Hysteria2 → VLESS/REALITY), каждый — только после сквозных проверок наравне с sing-box | пользователь сразу получает системный VPN; зависимость от Go уменьшается постепенно и без риска | дольше всего до «чистого Rust»; две реализации на переходный период |
| Г. Помощник launchd вместо Network Extension | не нужен аккаунт Apple Developer | не «нативный» VPN: нет в системных настройках; нужен пароль администратора при установке |

## Решение

**Движок — вариант А: свой на Rust с нуля** (выбор владельца 2026-11-12).
Новый крейт `gorion-engine` в `core/`: входы (локальный прокси, затем TUN),
маршрутизатор, исходящие протоколы. Из сторонних крейтов — только
криптография, TLS, QUIC и асинхронность (RustCrypto, rustls/BoringSSL,
quinn, tokio); протоколы и их форматы пишем сами.

Порядок протоколов — от простого к сложному, каждый закрывается сквозной
проверкой на стенде против сервера sing-box (правило 1):

1. Shadowsocks AEAD (aes-128-gcm, aes-256-gcm, chacha20-ietf-poly1305), direct.
2. Shadowsocks 2022, Trojan (TLS).
3. VLESS (TCP/TLS), транспорты ws, grpc, httpupgrade.
4. Маскировка TLS под Chrome (BoringSSL), REALITY, Vision.
5. Hysteria2, TUIC (QUIC), AnyTLS, VMess.
6. TUN: устройство + свой стек TCP/IP, DNS, раздельное туннелирование.

Пока протокол не прошёл проверку, его серверы подключаются через sing-box,
как сейчас. sing-box уходит из сборки, когда движок покроет всё.

**Системный VPN — вариант Г, помощник launchd** (выбор владельца
2026-11-12: «Помощник с паролем»). Network Extension без платного аккаунта
Apple невозможен: права `packet-tunnel-provider` выдаёт только Apple.

Как устроен помощник:

- Бинарник `gorion-helper` (крейт `core/crates/gorion-helper`) лежит в
  приложении: `Gorion.app/Contents/Helpers/gorion-helper`.
- Установка — один раз, с паролем администратора. Приложение просит macOS
  запустить `gorion-helper install` от root (`osascript … with administrator
  privileges`). Тот копирует себя и sing-box в
  `/Library/Application Support/Gorion/bin/` (root:wheel, 0755), пишет
  `/Library/LaunchDaemons/app.gorion.privileged-helper.plist` и запускает
  службу. Метка та же, что у Flutter-версии: новая служба заменяет старую.
- Связь — строки JSON через Unix-сокет
  `/var/run/app.gorion.privileged-helper.sock` (root:admin, 0660). Подключиться
  могут только администраторы — как во Flutter, где токен лежал в файле
  root:admin 0640. Токен больше не нужен: права проверяет система.
- Команды: `hello` (версия протокола 3), `start`, `stop`, `state`, `logs`.
  Помощник запускает только режим TUN; шаблон подписки собирается и
  очищается уже внутри помощника.
- **Подключение — это аренда.** После `start` соединение остаётся открытым.
  Закрылось (приложение вышло или упало) — помощник сразу останавливает
  sing-box, и маршруты возвращаются. Во Flutter помощник раз в 2 с проверял
  PID владельца через `ps`; аренда срабатывает мгновенно и не путается с
  чужим процессом с тем же PID (Δ в parity.md).
- Неожиданный выход sing-box помощник сообщает по той же аренде
  (`exited`), приложение показывает это как обычный сбой ядра.
- При старте службы помощник убирает остатки прошлой сессии
  (`recover_previous_session`) — после сбоя или перезагрузки сеть не
  остаётся завёрнутой в мёртвый туннель.
- В режиме TUN ядро работает от root, поэтому из шаблона дополнительно
  вырезаются ссылки на локальные файлы (ключи `*_path`, локальные rule-set).

Минусы, которые принимаем: VPN не виден в «Системных настройках → VPN»;
стандартный пользователь без прав администратора режим «Весь компьютер»
включить не может.

## Последствия

- Нет Go и отдельного процесса после завершения перехода; одна библиотека
  для macOS и Windows.
- Работы на месяцы. Самые рискованные части — маскировка TLS и REALITY:
  ошибка там означает блокировку, поэтому они идут после простых протоколов
  и только со сквозной проверкой против эталонного сервера.
- Для каждого протокола — тесты формата (векторы) и проверка совместимости с
  sing-box на стенде.
- На главном экране — одна кнопка: VPN для всего компьютера. Режимы
  «Только системный прокси» и «Вручную» остаются для опытных — в меню
  «Подключение» (позже — в настройках).
