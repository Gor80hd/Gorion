# ADR-0004. Всё движение — физическое

Статус: принято · 2026-11-11

## Решение

Каждое движение интерфейса описывается физикой, а не длительностью и кривой:

- **Пружина** `(response, bounce)` — для перехода между состояниями. Разгон
  возникает из силы пружины, торможение — из демпфирования.
- **Сохранение скорости** — новая цель подхватывает текущую скорость;
  анимация никогда не начинается с нуля посреди движения.
- **Передача скорости жеста** — отпущенный элемент продолжает с той скоростью,
  с которой его отпустили.
- **Инерция (затухание)** — свободный полёт после броска с трением, затем
  пружина к ближайшей точке притяжения.
- **Резинка** — сопротивление за пределами допустимого диапазона.

Параметры — только из `design/tokens.json` → `motion`. Таблица и формулы — в
`DESIGN.md` → «Движение».

## Почему `(response, bounce)`

Это параметризация SwiftUI (`Spring(duration:bounce:)`): на macOS токены
передаются без преобразований, а на Windows решатель реализуется по формулам
`stiffness = (2π / response)²`, `damping = 4π(1 − bounce) / response`, `mass = 1`.
Те же формулы уже работают во Flutter-версии (`lib/core/motion/spring_motion.dart`).

## Запрещено

Линейные анимации и кривые `ease-*` для движения, позиции и масштаба.
Исключения: бесконечные индикаторы (вращение, бегущая полоска) и
синхронизация с реальным временем (прогресс загрузки).
