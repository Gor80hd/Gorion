# План переноса Gorion с Flutter на нативные приложения

Статус: в работе. Начат 2026-11-11. Последнее обновление: 2026-11-12.
Ветка-источник: `refactor/core-cleanup` (Flutter, ~39 тыс. строк Dart, 60 тестовых файлов).

## Почему

Flutter рисует интерфейс сам. На macOS настоящий Liquid Glass приходится
подкладывать нативными `NSView` под прозрачный Flutter-слой и синхронизировать
их геометрию через канал (`macos/Runner/MainFlutterWindow.swift`,
`lib/core/window/window_surfaces.dart`). Стекло не преломляет Flutter-контент,
системные контролы недоступны, а каждое улучшение интерфейса упирается в мост.
На Windows та же история с акрилом. Отсюда решение: нативный интерфейс на каждой
платформе и одно общее ядро.

## Целевая архитектура

```
core/                      Cargo workspace — вся логика, одна на обе платформы
  crates/gorion-core       профили, разбор ссылок, сборка конфига sing-box,
                           автовыбор, замеры, раздельное туннелирование,
                           настройки, жизненный цикл runtime, Clash API
  crates/gorion-platform   системный прокси, процессы, watchdog — cfg по ОС
  crates/gorion-helper     привилегированный помощник (launchd / служба Windows)
  crates/gorion-ffi        UniFFI-привязки для Swift
apps/
  macos/                   SwiftUI-приложение, Liquid Glass, macOS 26+
    Gorion.xcodeproj
    Packages/GorionDesign  токены (генерируются), пружины, компоненты
    Packages/GorionKit     Swift-обёртка над ядром (XCFramework + биндинги)
  windows/                 Rust-приложение, акрил, Windows 11
design/
  tokens.json              единственный источник токенов дизайна
docs/
  migration/               этот план и таблица паритета
  adr/                     принятые решения
lib/, macos/, windows/ …   Flutter — живёт до этапа 6, только исправления
```

Решения и альтернативы: [ADR-0001](../adr/0001-shared-rust-core.md) (общее ядро на Rust),
[ADR-0002](../adr/0002-macos-swiftui-liquid-glass.md) (SwiftUI + Liquid Glass),
[ADR-0003](../adr/0003-windows-ui-stack.md) (стек интерфейса Windows — через спайк),
[ADR-0004](../adr/0004-physical-motion.md) (физическая модель движения).

## Принципы переноса

1. **Паритет до улучшений.** Сначала новое приложение делает всё, что делает
   Flutter-версия, и не хуже. Улучшения дизайна идут после паритета или
   явно помечаются в [parity.md](parity.md) как «меняем».
2. **Поведение фиксируется до переписывания.** Для каждой подсистемы ядра
   Flutter-версия выгружает золотые фикстуры (вход → выход), и Rust-реализация
   обязана их воспроизвести. Так перенос не теряет годы исправлений из
   [runtime-audit.md](../runtime-audit.md).
3. **Ядро не знает об интерфейсе.** Никаких строк для пользователя в `gorion-core`:
   ядро отдаёт коды и данные, тексты живут в приложениях.
4. **Один источник дизайна.** Цвета, отступы, скругления, шрифты и пружины —
   только из `design/tokens.json`. Значения в коде вручную не пишутся.
5. **Flutter заморожен.** В `lib/` только исправления критичных ошибок до этапа 6.
6. **Данные пользователя сохраняются.** Новое приложение использует тот же
   bundle id `app.gorion.client` и читает существующие JSON-файлы настроек и
   подписок из Application Support (форматы фиксируются фикстурами).

### Этап 1б — Свой движок подключения (`gorion-engine`, ADR-0005)

Каждый протокол закрывается сквозной проверкой против сервера sing-box на
стенде; до этого его серверы подключаются через sing-box.

- [x] Shadowsocks AEAD (aes-128-gcm, aes-256-gcm, chacha20-ietf-poly1305), direct, локальный вход SOCKS5/HTTP — совместимость с сервером sing-box проверена тестом (`GORION_SINGBOX`) и вживую через интернет; скорость наравне с клиентом sing-box, память 3,5 МБ против 34 МБ
- [x] Движок в приложении: профиль, который движок понимает целиком (Shadowsocks AEAD и 2022, Trojan, VLESS, транспорты WebSocket, HTTPUpgrade и gRPC, direct), идёт через `gorion-engine`, в режиме TUN — тоже (через помощника); остальное — через sing-box. Движок не запустился — та же попытка через sing-box. Не нашлось рабочего сервера — повтор через sing-box. Проверено вживую в приложении (ручной режим: REALITY + Vision; Trojan и Shadowsocks 2022; VLESS + WebSocket + TLS и Trojan + gRPC + TLS)
- [x] Shadowsocks 2022 (aes-128-gcm, aes-256-gcm, chacha20-poly1305, цепочка ключей iPSK:uPSK), Trojan поверх TLS — проверено тестом против сервера sing-box (`singbox_trojan_tls_and_ss2022_interop`, в том числе сервер, который говорит первым) и вживую в приложении
- [x] VLESS: TCP, REALITY и обычный TLS — проверено тестом против сервера sing-box (`singbox_vless_interop`, `singbox_trojan_tls_and_ss2022_interop`) и вживую через пример `mixed_proxy` со ссылкой `vless://`
- [x] Транспорты для VLESS и Trojan: WebSocket (ранние данные в заголовке или в пути), HTTPUpgrade, gRPC (все потоки к серверу — в одном соединении HTTP/2, в том числе поверх REALITY и без TLS). Проверено тестом против сервера sing-box (`singbox_transports_interop`) и вживую в приложении. Транспорты HTTP и QUIC — через sing-box
- [x] Обычный TLS в своём клиенте: цепочка до общих корней (webpki), имя сервера, подпись CertificateVerify (ECDSA, RSA-PSS), сжатые сертификаты brotli, `insecure` и свой сертификат (`certificate`). Проверено на сервере sing-box и на настоящих сайтах (`GORION_NET_TLS=1`). Только TLS 1.3: сервер, который умеет лишь TLS 1.2, не подключится
- [x] Маскировка TLS под Chrome (свой клиент TLS 1.3, ClientHello как у Chrome 133 без X25519MLKEM768 — как REALITY-клиент sing-box), REALITY, Vision с прямым копированием — внутренний TLS 1.3 через сервер sing-box идёт напрямую в обе стороны; чужой ключ или short id — отказ, а не подключение к настоящему сайту
- [ ] Hysteria2, TUIC (QUIC), AnyTLS, VMess
- [ ] UDP через прокси
- [~] TUN, первый срез (macOS): utun, адреса и маршруты как у sing-tun, системный стек — TCP через NAT в ядро, DNS приложений через выбранный сервер по DNS-over-HTTPS, сокеты к серверам привязаны к физическому интерфейсу, имена серверов разрешаются до подъёма туннеля. Помощник ставит движок рядом с sing-box и берёт его, если `gorion-engine check` принял профиль с TUN. Проверено тестами без root (пакеты, NAT, стек, DNS, разбор настроек) и DoH через движок на настоящем 1.1.1.1. **Вживую с root не проверено** — владелец отложил переустановку помощника

- [x] Системный VPN: помощник launchd (выбор владельца, ADR-0005) — сделан на sing-box; свой TUN — строкой выше
- [~] sing-box убран из сборки macOS (решение владельца 2026-11-12 — проверять своё ядро): в приложении и у помощника только `gorion-engine`, откатов нет, неподдержанный профиль — ошибка `EngineUnsupported` с причиной.   внутреннем TLS 1.3. В приложение движок ещё не подключён — все серверы
  пока идут через sing-box.

- **2026-11-12.** Движок подключён к приложению. `gorion-engine` — отдельный
  бинарник рядом с sing-box в `Contents/Resources`; он читает тот же конфиг
  sing-box, что строит ядро, и отвечает на нужную ядру часть Clash API
  (`/version`, `/proxies`, выбор сервера, URL-тест, `/traffic`). Ядро сначала
  спрашивает `gorion-engine check`: подошёл профиль и режим не TUN — запускает
  движок, иначе sing-box. Всё остальное (аренда системного прокси, метки,
  сторож, остановка, неожиданный выход) общее. Если через движок не нашлось
  рабочего сервера, ядро повторяет подключение через sing-box. Вживую:
  приложение в ручном режиме подключилось к локальному серверу REALITY +
  Vision через движок, проверки после подключения прошли, график скорости
  берёт данные из `/traffic` движка.

- **2026-11-12.** В движок добавлены Trojan и Shadowsocks 2022, а VLESS
  научился ходить через обычный TLS. Для этого свой клиент TLS 1.3 теперь
  проверяет цепочку сертификатов до общих корней (webpki) и принимает
  сжатые сертификаты: Chrome их предлагает, и настоящие сайты ими
  пользуются — без этого Cloudflare рвал рукопожатие. Совместимость
  проверена против сервера sing-box, клиент TLS — на нескольких крупных
  сайтах. Вживую приложение подключилось через движок к локальным
  серверам Trojan и Shadowsocks 2022.

- **2026-11-12.** В движок добавлены транспорты WebSocket, HTTPUpgrade и
  gRPC — так устроены почти все подписки за CDN. Запрос Upgrade уходит с
  первыми данными (в нём ранние данные), а данные после него — только
  после ответа 101: серверы Xray на gorilla рвут подключение, если данные
  пришли раньше. gRPC держит одно соединение HTTP/2 на сервер, как
  sing-box; кадры HTTP/2 — крейт `h2`, формат gun — свой. Против сервера
  sing-box проверены восемь сочетаний, включая REALITY + gRPC. Вживую
  через приложение: VLESS + WebSocket + TLS и Trojan + gRPC + TLS, восемь
  потоков gRPC шли по одному TCP-подключению.

- **2026-11-12.** Первый срез своего TUN (выбор владельца: «TCP ядра
  через NAT», «TCP + DNS»). Устроен как системный стек sing-tun на macOS:
  utun, адреса 172.19.0.1/30 и fdfe:dcba:9876::1/126, восемь поддиапазонов
  маршрутов с шлюзом на адрес туннеля. Сегмент приложения перезаписывается
  в подключение к слушателю движка, ядро само держит TCP, движок по порту
  NAT узнаёт цель и ведёт её через выбранный сервер. Запросы DNS на порт 53
  движок отправляет через сервер на 1.1.1.1 по DoH; остальной UDP получает
  «порт недоступен», чтобы QUIC сразу уходил на TCP. Сокеты движка к
  серверам привязаны к физическому интерфейсу (`IP_BOUND_IF`), имена
  серверов разрешаются до маршрутов. Без своего `unsafe`: utun через `nix`,
  адреса и маршруты — `ifconfig` и `route`. Помощник ставит движок вместе с
  sing-box; не поднялся — повтор через sing-box. Живая проверка с root
  отложена владельцем. Два сквозных теста с sing-box
  (`singbox_vless_interop`, иногда `singbox_trojan_tls_and_ss2022_interop`)
  на этой машине сейчас падают по таймауту и на прошлом коммите — при
  включённом стороннем VPN; к TUN это не относится, разобраться отдельно.

- **2026-11-12.** По решению владельца sing-box убран из сборки macOS,
  чтобы проверять только своё ядро. Без sing-box ядро не откатывается:
  отказ `gorion-engine check` — ошибка `EngineUnsupported` с причиной.
  Помощник (протокол 4) ставит движок и удаляет старую копию sing-box. Что
  осталось — [engine-next.md](engine-next.md).
