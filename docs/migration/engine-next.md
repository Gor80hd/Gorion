# Своё ядро: состояние и что доделать

Документ для продолжения работы с нуля: что уже сделано в своём движке
`gorion-engine` (ADR-0005), как его проверять и что осталось. Обновляйте его
вместе с [PLAN.md](PLAN.md) и [parity.md](parity.md).

Состояние на 2026-11-16, ветка `native-port`.

## Главное

- **В сборке macOS нет sing-box** (решение владельца 2026-11-12: проверять
  именно своё ядро). Приложение кладёт в `Contents/Resources/` только
  `gorion-engine`; помощник ставит в `/Library/Application Support/Gorion/bin/`
  себя и движок, а старую копию sing-box удаляет.
- Без sing-box откатов нет. Если профиль движку не по силам, человек видит
  ошибку `EngineUnsupported` («Gorion пока не умеет подключаться к этой
  подписке…»), а под «Подробнее» — причину от `gorion-engine check`: протокол и
  номер сервера или настройка. Мёртвый сервер даёт обычную ошибку
  `InternetUnavailable`, без второй попытки.
- Код поддержки sing-box в ядре остался (`runtime/service.rs`): если положить
  `sing-box` рядом с движком, вернутся проверка через sing-box и откаты.
  Совсем удалить его — пункт ниже.
- Протокол помощника — 4. Помощник версии 3 (на sing-box) приложение считает
  устаревшим и показывает карточку «Обновить».

## Что умеет движок

Подробности и проверки — PLAN.md, этап 1б.

- Вход: локальный SOCKS5/HTTP (`mixed`) и Clash API (то, что нужно ядру:
  `/version`, `/proxies`, выбор сервера, задержка, `/traffic`).
- Протоколы: Shadowsocks AEAD и 2022, Trojan, VLESS (TLS, REALITY, Vision),
  Hysteria2 (QUIC, salamander, `server_ports` и смена порта по `hop_interval`;
  TCP и UDP), direct.
- Транспорты: TCP, WebSocket, HTTPUpgrade, gRPC (gun), XHTTP из Xray
  (packet-up, stream-up, stream-one; HTTP/3, HTTP/2 и HTTP/1.1;
  `downloadSettings`, обфускация паддинга, размещения сессии, номера и
  данных, свой метод). XHTTP в настройках — `{"type": "xhttp", …}` с полями Xray в snake_case
  (см. `core/crates/gorion-core/src/parser/xhttp.rs`).
- UDP: вход SOCKS5 UDP ASSOCIATE и TUN; через сервер — только Hysteria2 и
  direct.
- TLS: свой клиент TLS 1.3, ClientHello как у Chrome, проверка цепочки
  (webpki), сжатые сертификаты.
- TUN (только macOS, первый срез): utun, маршруты как у sing-tun; TCP идёт
  через NAT в ядро macOS (системный стек); DNS на порт 53 уходит через
  выбранный сервер по DoH на 1.1.1.1; остальной UDP идёт через сервер, если
  тот умеет UDP, иначе — «порт недоступен». Код: `core/crates/gorion-engine/src/tun/`.

## Как проверять

Все команды — в разделе «Команды» AGENTS.md. Сквозные тесты: Hysteria2 —
против sing-box (`GORION_SINGBOX`), XHTTP — против Xray (`GORION_XRAY`).

1. Собрать: `core/scripts/build-xcframework.sh debug`, затем `xcodegen` и
   `xcodebuild`.
2. Режимы «Вручную» и «Только системный прокси» работают сразу.
3. Режим «Весь компьютер» (TUN):
   - нужен помощник новой версии — в приложении появится карточка «Обновить»
     (пароль администратора), или командой из AGENTS.md;
   - другие VPN на время проверки выключить: два системных VPN мешают друг
     другу, а движок привязывает свои сокеты к физическому интерфейсу
     маршрута по умолчанию.
4. Какое ядро работает: `ps -Ao comm | grep gorion-engine`. Причина отказа
   движка — в тексте ошибки («Подробнее»). Журнал ядра хранится только в
   памяти процесса (`RuntimeService::logs`); файла журнала пока нет.

## Не проверено

- **TUN вживую с root не запускался ни разу.** Это первое, что нужно сделать.
  Проверить:
  - что `curl` без прокси идёт через сервер;
  - что DNS идёт через DoH;
  - смену Wi-Fi на кабель;
  - что маршруты пропадают после остановки (`netstat -rn`);
  - что маршруты пропадают после `kill -9` движка — маршруты живут, пока жив
    utun.
- Настоящие серверы из подписок владельца на движке (проверялись только
  локальные серверы sing-box и Xray).
- XHTTP через настоящий CDN (Cloudflare и др.) и Hysteria2 на настоящем
  сервере (в том числе HTTP/3, `downloadSettings` и смена порта); Hysteria2
  и XHTTP в самом приложении (проверялись тестами и процессом
  `gorion-engine`).
- UDP в TUN вживую (QUIC браузера, звонки через Hysteria2): проверен только
  тестом ретранслятора без устройства.

## Что доделать — по порядку

1. **Живая проверка TUN** (см. выше). Ожидаемые слабые места:
   - адрес IPv6 может не сразу подойти для слушателя: есть повтор 3 с, иначе
     TCP по IPv6 отклоняется;
   - физический интерфейс опрашивается раз в 5 с;
   - имена серверов разрешаются один раз при подъёме туннеля и не обновляются.
2. **UDP через другие протоколы**: Shadowsocks, Trojan и VLESS (XUDP/mux у
   VLESS). Вход SOCKS5 и TUN уже готовы (`src/udp.rs`, `src/tun/udp.rs`):
   нужен вариант `UdpSession` для протокола. Без этого через них не
   работают QUIC/HTTP3, игры, звонки.
3. **Протоколы, которых нет**: TUIC (QUIC уже есть — quinn, как у
   Hysteria2), AnyTLS, VMess. Сейчас профиль, где есть хоть один такой
   сервер, целиком получает `EngineUnsupported`. У Hysteria2 нет Brutal
   (скорости `up_mbps`/`down_mbps`), перегрузкой управляет BBR.
4. **Отбор серверов вместо отказа всего профиля**: сейчас один непонятный
   сервер — отказ всему профилю. Лучше пропускать такие серверы при сборке
   конфигурации и показывать, что их нет.
5. **Маршрутизация**: правила из шаблона подписки, раздельное
   туннелирование (rule-set, домены, IP), sniff SNI в TUN (сейчас сервер
   получает IP цели, а не имя).
6. **DNS**: DNS из шаблона подписки, FakeIP, кэш. Сейчас в TUN годится только
   управляемый DNS ядра.
7. **TLS 1.2** в своём клиенте (серверы, которые умеют только 1.2), ECH.
8. **ICMP (ping) в TUN.**
9. **Windows**: TUN через Wintun, интерфейс (этап 5).
10. **Удалить sing-box совсем**:
    - код запуска и `check` sing-box в `runtime/service.rs`;
    - повтор через sing-box в `engine.rs` и флаг `singBoxOnly` в протоколе
      помощника;
    - `--singbox` у помощника;
    - переименовать `singbox_path` в FFI и Swift;
    - тексты ошибок «sing-box …» в `gorion-core/src/error.rs`.

    sing-box остаётся только тестовым сервером в сквозных тестах
    (`GORION_SINGBOX`).

## Известные проблемы

- `singbox_vless_interop` (и иногда `singbox_trojan_tls_and_ss2022_interop`)
  на машине владельца падают по таймауту — и на коммитах до TUN тоже. Это
  совпало с включённым сторонним VPN (Happ). Нужно перепроверить с
  выключенным VPN и, если не пройдёт, разобраться.
